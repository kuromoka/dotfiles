# くろもか文体

本人名義の文章を書く前に、[文体プロファイル](references/style-profile.md)を読む。本人がAIを使わずに書いたと確認できる文章の傾向は、出所が不明な過去記事の傾向より優先する。

## 書き方

1. 読者が最初に知りたい事実や、書こうと思ったきっかけから入る。大げさな前置きは置かない。
2. 日時、距離、金額、製品名、場所など、手元にある具体的な情報を使う。分からない情報は作らない。
3. 出来事を扱う文章では、基本的に起きた順で書く。持ち物、候補、比較、条件、手順など、本当に同じ種類の情報だけ箇条書きにする。経緯や感想は細かく箇条書きへ分けない。
4. 事実を説明したあと、短い感想や判断を添える。感情を盛ったり、教訓へ広げたりしない。
5. 本文は「です・ます」を基本にする。見出し以外では、名詞だけで文を終えない。
6. 中学生が一度読んで分かる言葉を選ぶ。カタカナ語、英字の略語、専門用語が必要なら、先に平易な説明を添える。
7. 絵文字は原則として使わない。感嘆符、疑問符、かっこ書きも、本人の軽い補足として効く箇所だけにする。
8. きれいに整えすぎない。全見出しを同じ型にしたり、各節を同じ長さにそろえたりしない。
9. 文章を短くすること自体を目的にしない。新しい事実、手順、結果がない前置きや一般論は足さず、同じ結論を別の言葉で繰り返さない。
10. 読みやすく見せるためでも、ユーザーの素材にない比喩、象徴的な意味、感情の深掘りを新しく作らない。材料が足りない場合は、飾った表現で補わず短く書く。
11. 太字は多用せず、記録、数値、用語、重要な条件など、拾い読みしやすくしたい短い部分を基本にする。各節へ機械的に置いたり、感情を強く見せるために文や段落全体を太字にしたりしない。

## natural-japaneseとの組み合わせ

同じ環境に `natural-japanese` がある場合は、その `SKILL.md` を読んでクイックモードを使う。下書きを一時ファイルへ保存し、同スキルの `scripts/lint.py` を `--genre essay --reading-load` 付きで実行する。指摘は一括置換せず、文体プロファイルと本文の意味を優先して直す。

このスキルと `natural-japanese` が食い違う場合は、次の順で判断する。

1. ユーザーが今回伝えた希望
2. 文体プロファイルの「避ける表現」
3. 文体プロファイルに記録した本人の傾向
4. `natural-japanese` の一般ルール

特に、すべての見出しを結論の文へ直さない。「当日」「記録」「感想」のような短い案内が読みやすい場合は残す。

## 仕上げ

次を確認し、違反があれば意味を変えない範囲で直す。

- 絵文字で感情を足していないか。
- 難しい漢字、カタカナ語、英字の略語を、説明なしで置いていないか。
- 日本語で言える内容を横文字へ置き換えたり、抽象的な言葉だけで具体的な行動を隠したりしていないか。
- 小説のような情景描写や、自分をよく見せるための言い回しを足していないか。
- 景色へ感情や人間らしい意志を重ね、自分の存在、居場所、生き方の話へ広げる叙情的な自己投影をしていないか。
- 本文に体言止めが残っていないか。
- 「重要なのは」「このように」「〜と言えるでしょう」など、なくても意味が変わらないAIらしい決まり文句がないか。
- 本人が提供していない経験、数字、感想、比喩、象徴的な意味を作っていないか。
- 最後を大きな教訓や抽象的なまとめにしていないか。
- 新しい情報のない前置き、一般論、同じ結論の言い換えで文章量を増やしていないか。
- 読点で別の話をつなぎ続けず、内容が変わる場所で文を分けているか。
- 感嘆符、疑問符、かっこ、省略記号を、各段落へ機械的に足していないか。
